# Кейс
Национальная сеть сэндвичных хочет внедрить услугу «заказать по факсу», но через Интернет (в дополнение к их текущей услуге факсимильной связи).

  Пользователи: тысячи, а возможно, когда-нибудь миллионы.

  Требования:

  - пользователи делают заказ, после чего получают время, когда можно забрать их сэндвич, и маршрут до магазина (который должен интегрироваться с несколькими внешними картографическими сервисами, включая информацию о пробках);
  - если магазин предлагает услугу доставки, отправить курьера с сэндвичем к пользователю;
  - доступность для мобильных устройств;
  - предложение национальных ежедневных акций/спецпредложений;
  - предложение локальных ежедневных акций/спецпредложений;
  - приём оплаты онлайн или при получении/доставке.

  Дополнительный контекст:
  Сэндвичные работают по модели франчайзинга, у каждой — разный владелец.
  Родительская компания в ближайшем будущем планирует выход на международный уровень.
  Корпоративная цель — нанимать недорогую рабочую силу для максимизации прибыли.

# Пользовательские сценарии
  
## Заказ сэндвичей

  1. Оформить заказ через интернет (веб или мобильное приложение)
  2. Выбрать ингредиенты для сэндвича
  3. Выбрать ближайший магазин для получения заказа
  4. Выбрать удобное время получения заказа
  5. Получить подтверждение заказа с номером и временем готовности

## Навигация и карты

  6. Получить маршрут к магазину после оформления заказа
  7. Видеть информацию о пробках на маршруте
  8. Получать уведомление о готовности заказа

## Доставка

  9. Заказать доставку на дом/офис
  10. Отслеживать курьера на карте в реальном времени
  11. Назначать курьеров на доставку (для владельцев магазинов)

## Мобильный доступ

  12. Сделать заказ с мобильного телефона
  13. Сохранить любимый заказ для быстрого повторного заказа
  14. Получать push-уведомления о готовности заказа и акциях

## Акции и предложения

  15. Видеть национальные ежедневные акции и спецпредложения
  16. Видеть локальные акции конкретного магазина

## Оплата

  17. Оплатить заказ онлайн при оформлении
  18. Оплатить заказ при получении в магазине (наличными или картой)
  19. Оплатить заказ при доставке

## Франчайзи / Магазины

  20. Управлять заказами своего магазина
  21. Устанавливать локальные акции и спецпредложения
  22. Настраивать доступное время и слоты для заказов

# Описание микросервисов
## 1. User Service

### Назначение
Управление аутентификацией, авторизацией и профилями пользователей.

### Зона ответственности
- Регистрация и вход пользователей
- Управление профилем пользователя
- Хранение избранных заказов
- Сессии и токены доступа

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| POST | /api/auth/register | Регистрация нового пользователя |
| POST | /api/auth/login | Аутентификация пользователя |
| POST | /api/auth/refresh | Обновление токена |
| GET | /api/users/{id} | Получение профиля пользователя |
| PUT | /api/users/{id} | Обновление профиля |
| GET | /api/users/{id}/favorites | Получение избранных заказов |
| POST | /api/users/{id}/favorites | Сохранение заказа в избранное |
| DELETE | /api/users/{id}/favorites/{orderId} | Удаление из избранного |

### Взаимодействие с другими сервисами
- **Order Service** — предоставляет данные о заказах пользователя для избранного

---

## 2. Menu Service

### Назначение
Управление меню, ингредиентами, ценами и их доступностью в магазинах.

### Зона ответственности
- Управление позициями меню (сэндвичи, напитки, гарниры)
- Управление ингредиентами и их вариациями
- Управление ценами
- Проверка доступности ингредиентов в конкретном магазине

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| GET | /api/menu | Получение полного меню |
| GET | /api/menu/{id} | Получение позиции меню |
| GET | /api/menu/categories | Получение категорий меню |
| GET | /api/menu/{storeId}/availability | Проверка доступности в магазине |
| GET | /api/ingredients | Получение списка ингредиентов |
| GET | /api/ingredients/{id} | Получение ингредиента |

### Взаимодействие с другими сервисами
- **Store Service** — запрашивает информацию о доступности ингредиентов в магазине
- **Order Service** — получает данные о меню для создания заказа

---

## 3. Store Service

### Назначение
Управление информацией о магазинах (франчайзи), их локациях, часах работы и настройках.

### Зона ответственности
- Управление списком магазинов
- Управление часами работы
- Управление контактной информацией
- Управление доступными временными слотами для заказов

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| GET | /api/stores | Получение списка магазинов |
| GET | /api/stores/nearby | Получение ближайших магазинов |
| GET | /api/stores/{id} | Получение информации о магазине |
| GET | /api/stores/{id}/hours | Получение часов работы |
| GET | /api/stores/{id}/slots | Получение доступных временных слотов |
| GET | /api/stores/{id}/promotions | Получение локальных акций магазина |

### Взаимодействие с другими сервисами
- **Promotion Service** — получает локальные акции для магазина
- **Order Service** — проверяет доступность магазина и слотов
- **Delivery Service** — получает информацию о магазине для доставки
- **Navigation Service** — использует координаты магазина для маршрутов

---

## 4. Order Service

### Назначение
Управление полным жизненным циклом заказа от создания до завершения.

### Зона ответственности
- Создание и валидация заказа
- Управление статусом заказа
- История заказов пользователя
- Интеграция всех компонентов заказа

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| POST | /api/orders | Создание нового заказа |
| GET | /api/orders/{id} | Получение заказа по ID |
| GET | /api/orders/user/{userId} | Получение заказов пользователя |
| PUT | /api/orders/{id}/status | Обновление статуса заказа |
| GET | /api/orders/{id}/status | Получение текущего статуса |
| DELETE | /api/orders/{id} | Отмена заказа |

### Взаимодействие с другими сервисами
- **Menu Service** — получает цены и доступность позиций меню
- **Store Service** — проверяет доступность магазина и слотов
- **Payment Service** — обрабатывает платеж
- **Delivery Service** — создаёт запрос на доставку
- **Notification Service** — отправляет подтверждение заказа

---

## 5. Payment Service

### Назначение
Обработка платежей онлайн и при получении.

### Зона ответственности
- Обработка онлайн-платежей через внешний Payment Gateway
- Проверка статуса платежа
- Обработка возвратов
- Поддержка оплаты при получении

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| POST | /api/payments/create | Создание платежа |
| POST | /api/payments/{id}/process | Обработка платежа |
| GET | /api/payments/{id}/status | Проверка статуса платежа |
| POST | /api/payments/{id}/refund | Возврат средств |
| POST | /api/payments/cod | Оплата при получении (cash on delivery) |

### Взаимодействие с другими сервисами
- **Order Service** — инициирует платёж при создании заказа
- **External Payment Gateway** — Stripe/PayPal для обработки платежей

---

## 6. Delivery Service

### Назначение
Управление доставкой заказов, назначение и отслеживание курьеров.

### Зона ответственности
- Управление заявками на доставку
- Назначение курьеров на заказы
- Отслеживание местоположения курьеров
- Интеграция с навигационными сервисами

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| POST | /api/delivery/request | Создание запроса на доставку |
| GET | /api/delivery/{orderId} | Получение информации о доставке |
| PUT | /api/delivery/{orderId}/assign | Назначение курьера |
| PUT | /api/delivery/{orderId}/status | Обновление статуса доставки |
| GET | /api/delivery/{orderId}/track | Отслеживание курьера (реальное время) |
| GET | /api/drivers | Получение списка курьеров магазина |

### Взаимодействие с другими сервисами
- **Store Service** — получает информацию о магазине
- **Navigation Service** — получает маршрут и данные о пробках
- **Notification Service** — уведомляет пользователя о статусе доставки

---

## 7. Navigation Service

### Назначение
Интеграция с внешними картографическими сервисами для навигации и информации о трафике.

### Зона ответственности
- Получение маршрута от пользователя до магазина
- Получение информации о пробках
- Расчёт ETA (estimated time of arrival)
- Предоставление ссылок на карты

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| GET | /api/navigation/route | Получение маршрута |
| GET | /api/navigation/traffic | Получение информации о пробках |
| GET | /api/navigation/eta | Расчёт времени прибытия |
| GET | /api/navigation/map-link | Получение ссылки на карту |

### Взаимодействие с другими сервисами
- **Store Service** — получает координаты магазинов
- **Delivery Service** — использует навигацию для маршрутов курьеров
- **External: Google Maps API** — основной источник карт и пробок
- **External: Apple Maps API** — дополнительный источник карт

---

## 8. Promotion Service

### Назначение
Управление национальными и локальными акциями и спецпредложениями.

### Зона ответственности
- Управление национальными акциями (едиными для всех магазинов)
- Управление локальными акциями (специфичными для магазина)
- Применение акций к заказу
- Управление расписанием акций

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| GET | /api/promotions/national | Получение национальных акций |
| GET | /api/promotions/local/{storeId} | Получение локальных акций магазина |
| GET | /api/promotions/active | Получение активных акций |
| POST | /api/promotions/apply | Применение акции к заказу |
| POST | /api/promotions | Создание акции (для админа/франчайзи) |
| PUT | /api/promotions/{id} | Обновление акции |
| DELETE | /api/promotions/{id} | Удаление акции |

### Взаимодействие с другими сервисами
- **Store Service** — получает информацию о магазине для локальных акций
- **Order Service** — применяет акции при создании заказа

---

## 9. Notification Service

### Назначение
Отправка уведомлений пользователям через различные каналы.

### Зона ответственности
- Отправка email-уведомлений
- Отправка SMS-уведомлений
- Отправка push-уведомлений
- Управление шаблонами уведомлений

### API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| POST | /api/notifications/email | Отправка email |
| POST | /api/notifications/sms | Отправка SMS |
| POST | /api/notifications/push | Отправка push-уведомления |
| POST | /api/notifications/order-confirmation | Уведомление о подтверждении заказа |
| POST | /api/notifications/order-ready | Уведомление о готовности заказа |
| POST | /api/notifications/delivery-update | Уведомление о статусе доставки |

### Взаимодействие с другими сервисами
- **Order Service** — вызывает уведомления при создании и изменении статуса заказа
- **Delivery Service** — вызывает уведомления о статусе доставки
- **External: Twilio** — отправка SMS
- **External: Firebase** — отправка push-уведомлений
- **External: SendGrid** — отправка email

---

## 10. API Gateway

### Назначение
Единая точка входа для всех клиентских запросов.

### Зона ответственности
- Маршрутизация запросов к микросервисам
- Аутентификация и авторизация
- Rate limiting
- Логирование и мониторинг

### Функции

| Функция | Описание |
|---------|----------|
| Routing | Перенаправление запросов к соответствующим сервисам |
| Authentication | Проверка JWT токенов |
| Rate Limiting | Ограничение количества запросов |
| SSL Termination | Терминация HTTPS |
| Load Balancing | Распределение нагрузки |

### Взаимодействие с другими сервисами
- Все внутренние сервисы доступны только через API Gateway
